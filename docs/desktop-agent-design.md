# ZT.AI Desktop Agent · 便携执行工作台

## 产品定位

ZT.AI Desktop Agent 是蔡宙廷的本机协作工作台，不是公开简历聊天页，也不是默认闲聊窗口。用户输入一个工作目标后，Agent 先拆解计划，再按权限调用本机工具，过程以执行日志、待批准动作和可验收结果呈现。

## 工作台结构

- 左侧：任务列表、新建任务、任务状态和最近执行记录。
- 中间：任务目标、执行计划、工具调用日志和最终结果。
- 右侧：模型切换、执行模式、工作目录、权限开关和待批准动作。
- 视觉：沿用 ZT.AI 网页端的淡灰、白色、金色 Logo、毛玻璃卡片和细线轨道；信息密度更高，强调工具与协作。

## 权限边界

默认只开放工作区读取。工作区写入和命令执行分别独立授权，可以单次批准，也可以在本机明确打开对应权限。所有路径都限制在工作区内；删除、覆盖、安装、外部发送等高风险动作仍然需要二次确认。权限作用于使用 Agent 的那台电脑，不会反向控制蔡宙廷的设备。

## 工具与模型协作

| 工具 | 默认权限 | 用途 |
| --- | --- | --- |
| `list_workspace` | 读取 | 查看工作区文件和目录 |
| `read_file` | 读取 | 读取文本文件并回传摘要 |
| `write_file` | 工作区写入 | 在工作区内新建或修改文件 |
| `run_command` | 命令执行 | 在批准后运行用户指定的测试或构建命令 |

模型不会直接获得操作系统权限。它先通过 `/api/agent/plan` 返回受约束的 JSON 计划；本机 Agent 只接受上述四种工具，并再次检查路径、文件大小和计划步数。模型要求写代码时返回完整文件内容，桌面端把写入目标和内容放入批准卡片，用户确认后才真正保存。模型规划失败时只执行安全的读取/检查步骤，不会落一份固定占位文件。

Agent 默认是执行模式，不是聊天模式。执行记录、工具返回值、批准动作和最终汇总会进入本机任务历史；切换 MiniMax M3 或 DeepSeek v4 flash 只改变推理模型，不改变工作区、权限和任务上下文。

## 模型与便携性

桌面端只保存工作台状态、任务日志、权限配置和本机执行确认，不把密钥写进前端。推理通过可替换的 ZT.AI Gateway `/api/agent/plan`、`/api/agent/chat` 路由完成，默认支持 MiniMax M3 和 DeepSeek v4 flash。写入和命令权限只有在当前设备明确确认后才能打开；撤销确认会自动关闭这两项权限。这个确认只约束运行 Agent 的设备，面试官下载后操作的是自己的电脑，不存在远程控制蔡宙廷电脑的通道。

项目使用相对路径、环境变量和静默启动脚本。Windows 上优先用 Edge `--app` 模式打开独立应用窗口，没有 Edge 时退回默认浏览器；整个压缩包不带 API key、`node_modules`、Git 元数据或运行历史，可以迁移到另一台电脑后重新配置环境变量运行。
