# ZT.AI 跨端专属声音对话设计

状态：已获用户认可，进入实现前设计冻结

## 目标

在不暴露任何 API Key 的前提下，让公开网页、ZT.buddy 桌面端和 Android 端都能使用蔡宙廷的专属克隆声音完成语音对话：用户按住或点击麦克风说话，系统把语音转成可编辑文字，经过现有聊天、联网核验和执行路由后生成回答，再用专属声音播报回答。

公开访客可以使用语音输入并听到专属声音；只有经过账户认证的本人可以录音、重新克隆、切换、删除或停用音色。

## 已确认的外部能力边界

- MiniMax 官方音色克隆接口接受 mp3、m4a、wav，原始克隆音频 10 秒至 5 分钟、单文件不超过 20 MB；可选的增强示例音频小于 8 秒、同样不超过 20 MB。
- 克隆得到的 `voice_id` 通过 MiniMax T2A 接口合成语音，API Key 只在 Render 网关保存。
- 当前公开 MiniMax 文档明确提供音色克隆和 TTS，但没有作为本项目唯一依赖的稳定 ASR 接口。因此语音转文字采用可替换的 ASR 适配器：首选网关配置的统一 ASR，浏览器原生识别只作为低延迟辅助或兜底。
- 两个用户提供的 MP4 只作为交互和配音流程参考，不作为默认克隆素材。除非用户明确确认其中音频是本人声音且允许使用，否则不上传给声音服务。

## 用户流程

### 本人首次设置声音

1. 在本人账户的声音设置中点击“录制我的声音”。
2. 页面给出一段中文普通话录音稿，提示安静环境、距离固定、不要背景音乐和混响。
3. 录制 30–90 秒即可开始首轮试听；如需更高相似度，可录制 2–5 分钟。
4. 客户端先检查格式、时长、大小和音量，再上传到网关；网关只在用户同意克隆/转写后把音频发送给已配置的语音服务，不向其他第三方扩散。
5. 网关上传 MiniMax、创建 `voice_id`，生成一段固定试听文本，返回试听音频和状态。
6. 用户确认后激活；不满意可以重新录制，旧音色和关联文件一并停用/删除。

### 普通语音对话

1. 点击麦克风开始录音，界面显示录音状态、计时和波形；再次点击或松开结束。
2. 先展示识别文字，用户可以修改；默认不因一次误识别直接执行本机敏感操作。
3. 点击发送后进入现有聊天流程，当前日期、联网核验、陌生事物检索、图片/文件分析和桌面执行规则保持不变。
4. 回答文字流式显示；回答完成后请求专属声音合成，消息下方出现音频播放器。
5. 用户可以播放、暂停、重播和关闭自动播报。浏览器禁止自动播放时，界面明确提示点击播放，不把失败伪装成成功。

### 独立语音模式与音频光球

- 点击现有麦克风按钮后进入独立语音模式，不把语音控件挤在移动端文字输入框里。
- 语音模式中心显示一个金色与薄荷绿色的 Canvas 光球，外围使用柔和的品牌光晕；底部保留退出、文字转写和播放控制。
- `listening` 状态读取麦克风 `AnalyserNode` 的音量与频谱，光球的半径、光晕和粒子强度随真实输入变化。
- `processing` 状态使用低幅度呼吸动画，并显示“正在整理你的话”；不把等待伪装成已经听懂。
- `speaking` 状态读取 TTS 音频元素的分析数据，光球按实际播报音量和频段跃动；点击光球可以立即停止播报。
- `idle`、`error` 和权限拒绝状态有明确的静态视觉和文字提示；浏览器或 WebView 无法提供分析数据时只使用低动效兜底，不生成虚假的音频波形。
- 网页、桌面端和 Android 复用同一套状态命名和交互契约；渲染实现可以分别适配 React、桌面静态页面和 WebView，但不能出现三套互相矛盾的行为。

## 跨端实现

### 共享网关接口

- `POST /api/voice/enrollment/upload`：本人上传录音，服务端校验并转交声音服务。
- `POST /api/voice/enrollment/clone`：创建/更新克隆音色并生成试听。
- `GET /api/voice/status`：返回是否已配置、是否可用、最近一次校验时间，不返回 API Key。
- `DELETE /api/voice`：本人停用并删除音色关联资源。
- `POST /api/voice/transcribe`：接收短时录音，调用配置的 ASR 适配器返回文字和置信信息。
- `POST /api/voice/synthesize`：接收回答文本，使用服务端保存的 `voice_id` 返回短期音频地址或受保护的音频响应。

所有接口都限制来源、请求体、时长、频率和文本长度；公开网页只允许转写和合成，不允许传入任意 `voice_id`。

### 网页端

- 把现有输入框旁的麦克风入口恢复为真实录音控件。
- 使用 `MediaRecorder` 采集浏览器可用格式；录音失败时保留文字输入。
- 公开网页首次播报前显示“AI 合成声音”提示，并保存用户的自动播报偏好。
- 不把原始录音写入 localStorage、GitHub Pages 或静态资源。

### ZT.buddy 桌面端

- 复用现有 `#voice-button`，移除当前“接入声音模型后可开始”的占位提示。
- 语音转写结果先进入任务输入框，保留编辑和审批机制；语音不能绕过本机执行权限。
- 回答音频和文本绑定到同一条会话消息，重启后只恢复受保护的音频引用，不保存 API 凭据。

### Android

- Manifest 增加 `RECORD_AUDIO`，运行时申请录音权限。
- `WebChromeClient.onPermissionRequest` 只允许受信任的 GitHub Pages 来源使用麦克风。
- 处理权限拒绝、WebView 不支持 `MediaRecorder`、网络中断和音频播放失败，均回退到文字输入。
- 不显示下载入口；底部导航和键盘弹出时保持输入框、录音按钮和播放控件可用。

## 可靠性与安全

- API Key、MiniMax 文件 ID、克隆 `voice_id` 只存在网关/服务端配置和受保护存储中，绝不进入 GitHub Pages、Android 包或桌面静态资源。
- 公开合成接口按访客、IP 和分钟级额度限流；相同回答缓存短期音频，避免重复计费。
- 语音转写和合成失败时显示具体的“语音暂时不可用”，同时保留文字回复和文字输入，不猜测、不伪造已播放状态。
- 文字回答仍由现有聊天路由负责：需要当前信息、新闻、陌生名词、具体事物或明确核实时先联网；联网失败不使用旧知识补猜。
- 录音设置中提供删除入口，并记录最小化的状态遥测，不记录公开访客的原始音频内容。
- 公开播放增加明确的 AI 合成标识，防止访客误认为是本人实时发声。

## 验收标准

- 三端均可完成：录音 → 转写 → 编辑 → 发送 → 文字回答 → 专属声音播放。
- 录音权限允许、拒绝、取消和超时四种路径都有可操作反馈。
- 中英文界面至少覆盖按钮、录音状态、转写状态、播放状态和错误提示。
- 原有联网来源抽屉、文件/图片分析、桌面权限审批和 MMX 生图/生视频不回归。
- 自动播放失败时仍能手动播放；音频地址过期或服务失败时可以重新生成。
- 不把任何用户录音、MiniMax API Key、文件 ID 或 `voice_id` 写入 GitHub。

## 实现顺序

1. 先完成服务端音频契约、TTS 适配器、ASR 适配器和受保护音频响应。
2. 再完成网页和桌面端共享录音/播放组件。
3. 完成独立语音模式和音频光球，使用测试音频或本地合成音频验证状态变化；不等待正式本人录音。
4. 接入 Android 权限与 WebView 麦克风桥接。
5. 使用一段测试音频跑通克隆、试听和删除；用户提供本人录音后再创建正式声音。
6. 运行针对性测试、三端构建、网关健康检查和 Pages/Release 发布验证。
