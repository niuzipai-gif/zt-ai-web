# 网页基础文件分析设计

## 状态

已获用户确认的范围，待用户审阅本设计后进入实现计划。

## 背景

网页公开聊天的附件流程目前只在浏览器内处理图片、PDF、DOCX 和纯文本。`package.json` 已经包含 `xlsx`，但 `src/main.jsx` 没有调用它；因此 `.xlsx/.xls` 会落入“只读取文件名和类型”的兜底分支。发送给网关的 `messages` 里没有工作簿内容，网关也只收到附件元数据，所以模型无法分析截图中的 Excel 文件。

本次改动聚焦网页端基础文件分析。原始文件仍留在浏览器，不新增公开文件上传接口；浏览器只把经过限制、清洗和结构化的摘要作为聊天上下文发送给现有网关。

## 目标

1. 网页端可以分析常见的 `xlsx`、`xls`、`csv`、`pdf`、`docx`、`txt`、`md` 和 `json` 文件。
2. 表格文件不是简单拼接原始单元格，而是生成包含工作表、表头、行列规模、空值和数值统计、代表性样本的可读摘要。
3. 解析结果进入用户消息的模型上下文，模型必须优先使用已解析的数据，不得因为附件问题编造结论。
4. 附件卡片能区分已读取、已截断、解析失败和仅有图片预览等状态。
5. 文件解析失败时给出具体、可执行的处理建议，并把失败原因作为受控提示传给模型；不把浏览器底层异常直接展示给用户。
6. 保持现有图片多模态输入、PDF/DOCX/纯文本读取、历史会话和公开聊天协议兼容。

## 非目标

- 本次不新增网关原始文件上传、对象存储或临时文件服务。
- 本次不承诺扫描型 PDF 的 OCR，不实现旧式二进制 `.doc` 的解析。
- 本次不改变桌面端和安卓端的本地文件运行时；它们继续使用各自的附件能力。
- 本次不把完整工作簿或完整文本无上限地发送给模型。
- 本次不改变联网检索规则；外部资料检索仍由现有研究路由决定，文件中已有的数据不因普通文件分析自动触发联网。

## 方案比较

### 方案 A：浏览器本地解析（推荐）

复用现有 `xlsx`、`pdfjs-dist` 和 `mammoth` 依赖，在 `src/lib/attachment-reader.js` 统一完成类型识别、解析、摘要和限制，再由 `src/main.jsx` 把摘要加入用户消息文本。

- 优点：不需要上传原始文件，改动集中，适合 GitHub Pages 的静态前端，现有网关协议基本不变。
- 代价：浏览器内存和文件大小需要设置上限；超大或加密文件仍需明确提示。

### 方案 B：网关接收原文件后解析

网页上传原文件，由网关使用 Node 解析并把摘要交给模型。

- 优点：便于统一处理大文件和复用到多个客户端。
- 代价：需要新增上传接口、临时存储、清理、限流、鉴权和隐私说明，不适合本次小范围修复直接引入。

### 方案 C：浏览器把原文件编码后直接塞入聊天请求

把文件转成 Base64 或二进制字符串发送给模型网关。

- 优点：前端实现路径短。
- 代价：请求体膨胀、模型无法直接理解 Office 二进制、隐私和限流边界不清晰，不能作为文件分析协议。

## 详细设计

### 1. 统一附件读取器

扩展 `src/lib/attachment-reader.js`，保留现有 PDF 和纯文本接口，并增加：

- `isSpreadsheetAttachment(file)`：按 MIME 和扩展名识别 `xlsx`、`xls`、`csv`。
- `extractSpreadsheetText(file)`：读取 ArrayBuffer，解析工作簿并返回结构化中文摘要。
- `attachmentReadStatus` 或等价的受控结果字段：`ready`、`truncated`、`error`、`preview-only`。
- 统一的摘要上限常量和用户可读错误映射，避免 `xlsx`、PDF、DOCX 各自定义不同的失败行为。

`prepareAttachment` 的分支顺序调整为：图片 → 表格 → PDF → DOCX → 普通文本。这样 `csv` 不会先被当成未经整理的纯文本发送。

### 2. Excel/CSV 摘要内容

`extractSpreadsheetText` 使用 `xlsx` 读取工作簿，按工作表生成以下内容：

- 文件名、格式、工作表名称和工作表数量。
- 工作表的有效范围、行数、列数和规范化后的表头。
- 空值数量或空值率较高的列。
- 数值列的非空数量、最小值、最大值、平均值和合计（可计算时）。
- 日期列和文本列的基本类型判断。
- 前若干行和末若干行代表性样本，保留列名，空单元格统一显示为 `空`。
- 公式单元格、错误单元格、合并单元格或未能识别的列的提示（有则显示）。

解析器不修改原文件，不执行公式，不访问外部链接；公式单元格优先使用工作簿里已有的缓存值，并在摘要中说明“公式未重新计算”。

为避免一个附件占满聊天上下文，摘要使用总字符上限。当前网关单条文本仍有 8,000 字符边界，第一版将把所有附件合并后的可发送摘要控制在该边界以内，并在截断时明确写入：`已显示统计和代表性样本，未包含全部行；如需继续分析，请指定工作表、列或筛选条件。` 统计优先于样本，工作表概览优先于重复数据。

### 3. 文本、PDF、DOCX 和 JSON

- `txt/md/csv` 等文本继续采用本地读取，但 `csv` 走表格解析器。
- PDF 沿用现有文字提取，保留页码和页数上限；没有可提取文字时提示可能是扫描件，建议上传截图。
- DOCX 沿用 Mammoth 纯文本提取；解析失败时只显示“暂时无法读取此 DOCX，请改用 PDF 或 TXT”，不显示内部组件堆栈。
- JSON 在现有文本读取基础上增加格式识别提示；有效 JSON 可使用稳定缩进或紧凑摘要，无效 JSON 仍保留受限原文并标记格式异常。

### 4. 模型上下文与防猜测规则

用户消息的文本上下文改为包含以下明确边界：

```text
[附件解析摘要]
文件：...
解析状态：已读取/已截断/解析失败
内容：...
[/附件解析摘要]
```

当存在 `已读取` 或 `已截断` 的附件摘要时，服务端公开人格提示增加以下约束：

- 先引用附件中实际出现的工作表、字段和数值，再给出分析。
- 不得把文件名、行业常识或旧知识当成文件里的数据。
- 摘要缺少某个字段、工作表或完整行时，明确说明“当前摘要未包含”，不能补猜。
- 用户要求精确计算但摘要不足时，先说明需要的工作表/列/筛选条件；不输出伪造的精确结果。
- 解析失败时直接解释失败原因和替代操作，不回答成“我已经分析了文件”。

文件摘要仍通过现有 `messages` 文本发送，附件二进制不进入网关；附件元数据继续用于遥测和界面历史，不记录原始文件。

### 5. 界面反馈

`AttachmentList` 根据读取状态显示：

- `已读取`：摘要已生成，可发送分析。
- `已截断`：已生成有限摘要，模型可先分析概况。
- `未解析`：解析失败，鼠标悬停或辅助文本显示可执行建议。
- 图片显示 `预览` 或现有图片状态，不影响多模态图片输入。

发送按钮不因为单个文件解析失败而静默放行。可以继续发送，但用户消息中必须带有受控的失败说明，模型只能解释缺口；若没有文字输入，也应把“请分析这个附件”作为默认请求，而不是只发送文件名。

### 6. 安全与资源边界

- 文件大小、摘要字符数、工作表数量和样本行数均设有常量上限。
- 解析过程只使用用户主动选择的 `File` 对象，不读取工作区、浏览器其他文件或本机路径。
- 不执行宏、外部链接、公式或嵌入对象。
- 不把 API key、文件二进制或原始图片写入代码、GitHub 或遥测。
- 解析异常在控制台仅保留必要诊断，用户界面使用稳定中文提示。

## 测试设计

### 单元测试

在 `src/lib/attachment-reader.test.js` 增加：

1. `xlsx`、`xls`、`csv` 的 MIME/扩展名识别。
2. 一个包含两张工作表、表头、空值、数字列和日期列的工作簿能生成工作表概览、表头和统计。
3. CSV 能走结构化表格摘要，不再按长文本原样拼接。
4. 公式、错误单元格和空工作表会生成受控提示。
5. 超过摘要上限时返回 `truncated`，并包含继续分析的说明。
6. 损坏或不支持的工作簿返回稳定错误信息，不泄露底层堆栈。
7. 现有 PDF、DOCX、纯文本分类测试继续通过。

### 集成与回归

- 构建测试确认 `xlsx` 浏览器包可被 Vite 正常打包。
- 公开聊天请求包含附件摘要，服务端不会只看到附件元数据。
- 文件解析失败仍能完成可理解的聊天回复，且不会展示原始工具协议或异常堆栈。
- 现有图片多模态、联网来源抽屉、会话历史、拖拽/粘贴附件和模型切换不回归。

## 验收标准

1. 上传截图中的 `.xlsx` 后，附件不再显示“未解析”，至少显示工作表、表头、行列规模和数据统计。
2. 发送“分析这个文件”时，回复必须引用文件实际解析出的字段或统计；不得仅根据文件名猜测，也不得直接声称“无法打开”。
3. 上传一个损坏或不支持的文件时，界面明确告诉用户失败原因和替代格式，模型不编造内容。
4. `csv`、`pdf`、`docx`、`txt/md/json` 和图片的既有能力保持可用。
5. 针对性单元测试、`npm test` 和 `npm run build` 通过；不删除 `.design-audit/` 或 `.runtime-qa/`。
