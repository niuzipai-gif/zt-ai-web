# ZT.buddy Codex 式桌面壳层与执行反馈设计

## 目标

修复当前桌面端中无效工作区入口、底层 tool-call/组件错误泄露、聊天历史操作缺失和顶部工具栏缺失的问题，让 ZT.buddy 的普通聊天与执行模式都拥有一致、自然、可恢复的工作台体验。

本次改造只针对桌面端壳层和展示边界，不改变已有账号、权限、模型路由、工作区安全边界和服务端数据结构。

## 用户可见结构

### 1. 融合式顶部工具栏

在 Electron 隐藏标题栏下增加一层与应用背景融为一体的应用工具栏，不再出现普通软件式的独立白色块。工具栏从左到右包含：

- 侧边栏收起/展开按钮；
- 应用内后退、前进按钮；
- 工作区标题与当前模式；
- 普通聊天 / ZT.buddy 模式切换；
- 刷新当前会话状态和账户状态。

窗口最小化、最大化和关闭继续由 Electron 标题栏覆盖层负责，颜色与工具栏保持一致。

### 2. 可收起的聊天列表

左侧聊天列表保留最近对话、新建对话和当前工作区状态。点击收起后，列表变为窄侧栏，仅保留 Logo、展开按钮和当前会话提示；状态写入本地存储，重新打开应用保持上次选择。

删除左下角“选择”按钮。工作区切换不再作为聊天列表底部的常驻操作，迁移到工具栏菜单或工作区设置入口，避免与聊天历史混淆。

### 3. 应用内前进/后退

前进/后退只操作 ZT.buddy 自己维护的会话状态，不调用浏览器历史。状态节点包含：模式、当前会话 ID、侧边栏展开状态和权限/工具抽屉状态。新建对话、点击历史会话、切换模式和打开抽屉都会形成可回退节点；连续点击前进/后退不会丢失已经保存的聊天内容。

无可回退或前进状态时按钮禁用，并提供明确的 aria-label 和 title。

## 展示边界与错误处理

### 1. 统一消息展示管线

模型或执行运行时返回的文本先经过展示层归一化，再交给 Markdown 渲染器。展示层必须过滤或折叠以下内部内容：

- `<think>...</think>`；
- `[toolcall]`、`<toolcall>`、`<minimax>` 等供应商协议标记；
- 原始 JSON 工具调用和内部事件帧；
- 仅供执行抽屉使用的调试内容。

工具调用仍然写入执行抽屉的活动日志，但不能作为普通 assistant 气泡的正文显示。

### 2. 执行中的轻量状态

任务运行时，在对应回答气泡下显示一行半透明、带轻微脉冲动画的最新状态，例如“正在读取工作区…”；状态更新只保留最新一行。完整步骤、权限请求和原始工具输出收进默认关闭的执行抽屉，用户主动展开后查看。

任务完成后，状态行变为简短结果摘要；错误只显示可理解的用户提示，原始错误详情留在抽屉日志中。

### 3. 附件与文档读取

客户端启动时检查 PDF/DOCX 阅读依赖是否实际可用。DOCX 读取组件未加载时，不把内部异常直接塞进聊天正文，而显示“暂时无法读取此文档，请重新打开或改用 PDF/文本文件”的可操作提示。对图片、PDF、DOCX、文本和拖拽/粘贴附件保持现有输入能力，不在本次设计中改变附件协议。

## 技术边界

主要改动位置：

- `agent-desktop/public/index.html`：顶部工具栏、折叠侧栏、状态行与抽屉语义结构；
- `agent-desktop/public/styles.css`：融合式工具栏、窄侧栏、动画和响应式状态；
- `agent-desktop/public/app.js`：应用内导航栈、侧栏状态、统一错误展示和按钮状态；
- `agent-desktop/public/attachment-reader.mjs`：文档读取能力检查和用户级错误映射；
- `agent-desktop/src/presentation.mjs` 或等价展示模块：内部协议清洗与摘要生成；
- 对应单元测试、渲染契约测试和打包后的桌面烟测。

不修改：账号服务、权限授权协议、网关 API、聊天数据存储格式和网页版页面。

## 验收标准

1. 桌面端左下角不再出现“选择”按钮，且没有死点击区域。
2. 顶部工具栏与应用背景统一，不产生独立白色横块。
3. 侧边栏可以收起、展开，刷新或重启后保持状态。
4. 后退/前进只切换应用内会话状态，并正确禁用边界按钮。
5. 普通聊天与 ZT.buddy 都不显示原始 tool-call、think 或供应商协议文本。
6. 执行中回答气泡下实时更新一行状态，完整日志默认收起到抽屉。
7. DOCX 组件缺失时只显示可理解提示，不出现“桌面端文档读取组件尚未加载”的底层错误。
8. 现有登录、注册、历史会话、新建对话、权限抽屉、文件拖拽/粘贴和模型切换测试全部通过。
9. 重新打包后，安装版启动到登录页，登录后普通聊天和 ZT.buddy 均能正常加载。

## 非目标

- 本次不重新设计移动端和网页版；
- 本次不开放新的本机权限，不改变完全访问的安全规则；
- 本次不删除任何账户、聊天记录或用户数据；
- 本次不把完整执行日志永久展示在聊天正文中。
