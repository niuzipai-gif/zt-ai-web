# ZT.buddy 桌面端 Soft Glass 视觉设计

## 目标

把 ZT.buddy 桌面端从“几个白色卡片拼在灰色背景上”调整为一张连续的高级工作台。整体参考 Codex 的自然层级，但保留 ZT.AI 的冷灰、白色与暖金品牌识别，重点改善长时间聊天、执行任务和切换模式时的空间感与稳定感。

## 已确认的设计方向

- 采用 A · Soft Glass 方向。
- 顶部原生菜单区、应用顶栏、页面背景和聊天工作区不能形成割裂的白色横条；它们共享同一套冷灰玻璃基底，视觉上像一整张连续的工作台。
- 毛玻璃只用于建立层级，不使用夸张透明、强烈渐变或过多悬浮卡片。
- 侧栏是轻量导航层，聊天区是主要视觉焦点，执行状态和权限抽屉属于可按需打开的辅助层。
- 保留现有功能结构：普通聊天 / ZT.buddy 切换、会话列表、附件、Skill、权限、模型选择、语音、执行过程抽屉。

## 视觉系统

### 空间与背景

- 页面底色使用极浅的冷灰蓝，并叠加两个低饱和、低对比环境光晕：右上暖金、左下灰蓝。
- 顶栏不使用不透明纯白；使用带透明度的冷灰白，并配合 `backdrop-filter: blur()` 和轻微饱和度增强。
- 原生窗口背景色与网页根背景保持一致，避免窗口边缘出现不同色块。

### 层级

- 主工作台与侧栏使用半透明白玻璃，边框采用低对比的白色高光和灰蓝描边。
- 聊天内容、输入框和状态卡使用更高不透明度，确保文字清晰和可读。
- 阴影统一使用大扩散、低透明度，不使用黑色硬边。
- 圆角保持中等偏大，但不让每个小控件都变成孤立胶囊。

### 品牌与状态

- ZT.AI Logo 保持统一图片资产，暖金只作为品牌、焦点和关键操作的点缀。
- 主操作使用深石墨色，成功使用薄荷绿，等待/授权使用暖橙金，错误使用低饱和红色。
- 执行中保留轻量脉冲和最新状态行；尊重 `prefers-reduced-motion`，降低动画而不隐藏状态。

## 交互与可用性

- 顶栏、模式切换、侧栏、聊天区和输入框均保留清晰的 hover / focus-visible 反馈。
- 玻璃层不能降低输入框、消息正文、模型名称和授权状态的对比度。
- 小屏幕继续使用单列布局；玻璃效果退化为较高不透明度，避免低端设备上文字发灰。
- 不改变当前会话、附件读取、权限审批或模型路由逻辑；本次只优化视觉层和与视觉直接相关的窗口背景。

## 实现边界

- 主要改动集中在 `agent-desktop/public/styles.css`，通过新增主题覆盖层降低对现有功能样式的影响。
- `desktop-app/main.mjs` 仅调整 Electron 原生窗口背景色，不启用无边框透明窗口，避免破坏系统菜单、拖动、最大化和系统级可用性。
- 增加渲染契约测试，锁定连续背景、玻璃层、焦点态和 reduced-motion 兜底。

## 验收标准

1. 1280×900 和 1480×920 下，顶部原生菜单、应用顶栏与工作台不再呈现割裂的纯白横条。
2. 侧栏、聊天区、输入区有清晰但克制的层级，主聊天区仍是视觉焦点。
3. 普通聊天与 ZT.buddy 切换后，玻璃层级和空间结构保持稳定。
4. 输入框、权限按钮、模型选择、发送按钮和抽屉具备可见的键盘焦点态。
5. `prefers-reduced-motion: reduce` 下不出现持续动画或明显位移。
6. 现有桌面端单元测试、渲染契约测试、构建与安装包自检全部通过。
