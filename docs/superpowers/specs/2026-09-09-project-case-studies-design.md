# ZT.AI 项目案例演示与 GitHub 入口设计

## 目标

让精选项目不再只是静态卡片：访客点击项目后，能够通过一段轻量、连续、可重播的流程动画理解项目是如何从输入走到结果的；同时让每个 GitHub 入口指向真实可访问、与项目内容相符的公开资料。

## 范围

本次包含：

1. 三个项目详情页的“实现演示”流程动画。
2. 动画的播放、重播、手动步骤查看、移动端布局和减少动态效果支持。
3. GitHub 入口的项目级映射。
4. 新建公开仓库 `zt-ai-project-case-studies`，上传三套脱敏后的操作流程说明。
5. 页面构建、仓库可访问性和线上链接验证。

本次不包含：

- 修改简历内容或模板。
- 上传供应商、客户、账号、密钥、内部链接或未授权数据。
- 把私有仓库 `kunxin-amazon-operations-development-experience` 暴露给公开访客。
- 为三个项目强行拆分成三个独立仓库。

## 公开仓库映射

| 项目 | 公开入口 | 说明 |
| --- | --- | --- |
| AI 选品与开品工作流 | `zt-ai-project-case-studies` | 公开展示脱敏后的流程、判断节点和验收标准 |
| 半小时套图生产方案 | `amazon-linkfox-image-sop` | 已存在的公开 LinkFox 工作流仓库 |

## 页面交互设计

### 项目详情页

现有详情页保留问题、贡献、实际执行链路、工具能力、结果边界和可验证入口，在“实际执行链路”之前增加实现演示卡片。

演示卡片包含：

- 一个标题和一句说明，明确这是流程演示而非实时业务数据。
- 五个步骤节点：输入、判断、执行、校验、结果；每个项目可使用自己的本地化步骤文案。
- 当前步骤的高亮状态、连接线进度和简短解释。
- “播放演示 / 重播”按钮，以及手动点击任一步骤的能力。
- 播放状态不会触发网络请求，不依赖外部服务，避免访客因服务延迟看不到演示。

### 动画行为

- 进入详情页后自动播放一轮，单步节奏舒缓，避免首屏突然跳动。
- 一轮结束后停在结果步骤，不无限循环，避免页面持续运动干扰阅读。
- 用户点击重播时重新从输入步骤开始。
- 用户点击任意步骤时立即切换到该步骤，并停止自动播放，方便阅读。
- `prefers-reduced-motion: reduce` 时取消位移动画，只保留清晰的状态切换。
- 页面离开或切换项目时清理计时器，不留下后台动画任务。

### 移动端

- 桌面端采用横向五步流程，移动端改为纵向流程。
- 节点文本保持可读，不使用过小字号或横向溢出。
- 重播按钮与步骤节点均保持足够触控面积。

## 数据与代码边界

- 项目动画数据放入 `src/lib/project-details.js`，与现有中英日项目详情数据保持同一来源。
- 动画组件只消费步骤数据和本地化 UI 文案，不直接读取业务 API。
- GitHub URL 作为明确的项目证据字段维护，不在 JSX 中散落硬编码。
- 新仓库使用 README 加三个项目 Markdown 文件；流程说明只保留方法、工具类别、判断顺序、验收标准和公开可引用的结果描述。

## 验证方案

1. 单元测试确认三个项目在中英日三种语言下都有五步动画数据和合法 GitHub URL。
2. 组件逻辑测试确认自动播放、手动选择、重播和减少动态效果分支行为。
3. 运行现有完整测试和生产构建。
4. 检查新仓库公开可访问、默认分支存在、README 与三个案例文件已上传。
5. 发布 Pages 后检查项目入口、GitHub 入口、详情页和移动端资源返回 200。
6. 确认源工作区只保留既有的 `.design-audit/` 与 `.runtime-qa/` 未跟踪目录，不删除或改写它们。

## 验收标准

- 三个项目点击后都能打开详情并播放一轮连贯的实现动画。
- 动画可以重播、手动查看步骤，手机端不横向溢出。
- 底部 GitHub 入口指向新公开案例仓库。
- 套图项目指向 `amazon-linkfox-image-sop`。
- 新仓库不包含敏感资料，且访客能从 README 找到三个项目的操作流程。
- 测试、构建、仓库访问和 Pages 线上检查均有实际输出作为证据。
