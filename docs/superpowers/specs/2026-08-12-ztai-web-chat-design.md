# ZT.AI 网页端对话与 MMX 创作设计

## 目标

将 ZT.AI 网页端收敛为“个人公开展示 + AI 对话 + MMX 媒体创作”产品。网页端不承载 Agent、工作台、本机执行、面试官授权或桌面端控制能力；这些能力留到网页上线稳定后另行设计。

## 产品范围

- 首页：ZT.AI 品牌、金色 Logo、退格重打动效和个人定位。
- 公开聊天：免费对话、MiniMax M3 / DeepSeek V4 Flash 切换、思考点点、流式回复、错误提示。
- 个人展示：简介、精选项目、简历摘要、公开 GitHub 精选内容。
- MMX 创作：隐藏在聊天链路中，仅当用户用自然语言明确提出生图或生视频需求时触发；不设置单独页面、公开导航或显式额度入口。
- 不包含：Agent 工具、工作台、本机执行、设备配对、Shell / PowerShell、沙箱、桌面端下载和面试官授权。

## 技术架构

```text
Vite React 前端
  ├─ 公开展示页面
  ├─ /chat 公开聊天
  └─ /media MMX 创作
          │
          ▼
轻量 Node 网关
  ├─ /api/chat       MiniMax M3 / DeepSeek V4 Flash，SSE
  └─ /api/media/jobs MMX 图片 / 视频异步任务
```

浏览器不持有模型密钥。后端通过环境变量访问模型服务，前端只提交模型别名、消息和媒体任务参数。聊天使用 SSE 事件 `message.start`、`message.delta`、`message.done`、`message.error`；媒体使用任务事件 `job.queued`、`job.running`、`job.completed`、`job.failed`。

## 体验与权限

- 公开聊天不调用任何 Agent 工具，不读取本地文件，不执行代码。
- MMX 在后端作为聊天链路的隐式媒体路由，图片和视频仍通过任务状态表达；普通聊天不触发媒体额度。
- 公开页面先采用轻量限流；媒体生成后端接入时需要增加额度、频率和单任务参数校验。
- 真实 API 接入前，用户提供的密钥必须轮换；密钥不能写入源码、前端构建产物、SQLite、日志或截图。

## 验收标准

- 桌面和手机端没有横向溢出，导航层级清晰。
- 聊天页只强调对话和模型切换，不出现 Agent 或工作台入口。
- MMX 有独立、可理解的生图 / 生视频页面，不与 Agent 权限混用。
- 当前本地模拟交互与后端接入后的 SSE / 异步任务状态在组件层保持一致。
- 构建通过，浏览器无控制台错误；后端接入后前端构建产物中不含密钥。
