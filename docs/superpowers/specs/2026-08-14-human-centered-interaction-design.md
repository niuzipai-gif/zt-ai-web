# ZT.AI 人本交互优化设计规格

## 目标

保留 ZT.AI 现有的浅灰、白色与金色品牌语言，解决“看起来精致，但首次使用不够顺手”的问题。公开网页要让面试官在第一次进入时立刻知道能问什么、从哪里开始；桌面端要让使用者始终清楚当前是在聊天、准备执行任务，还是正在执行任务。

本次改造遵循“会话优先、信息按需出现”的原则：核心输入和当前结果始终靠近用户；个人名片、历史、模型、工具、权限等辅助信息只在需要时展开，而不是长期占据主要视野。

## 已确认范围

### 公开网页

- 首页和整体品牌视觉继续使用现有金色 ZT.AI Logo、灰白毛玻璃、克制动效和三语内容；不重做品牌色、字体或页面结构。
- 给生产网页增加标准 favicon：使用同一张金色 ZT.AI Logo，提供浏览器标签页和快捷方式需要的 PNG/ICO/Apple 图标尺寸，并以 Vite 的 `BASE_URL` 引用，确保 GitHub Pages 的 `/zt-ai-web/` 子路径正常加载。
- 公开聊天页改为会话优先。桌面端保留左侧完整数字名片；手机端名片收缩为可展开摘要，聊天标题、示例问题和输入框应在首屏可见。
- 空会话不再只有一块大留白。欢迎区包含一句边界说明、三个与求职直接相关的可点击问题示例，以及“开始输入”主动作；点击示例只填入或立即发送用户可预期的提问。
- 顶部动作层级固定为：`新建聊天` 是唯一深色主按钮；`聊天记录`、`简历文件` 是次级按钮；“无需登录 · 免费”作为静态状态而不是竞争 CTA。
- 历史抽屉继续按访客隔离。会话标题由第一句自动生成，显示相对时间和消息数量；抽屉空状态只有在确实没有会话时出现，避免“新建聊天”按钮与空会话条目重复。
- 手机端保持底部导航，但输入区在聚焦、键盘弹出和滚动时不得被导航遮挡；所有触控按钮的实际点击区域不小于 44px，图标按钮保留可读标签或无障碍名称。
- 加载、网络慢、调用失败、附件不支持、会话为空等状态使用短句、可执行的恢复动作和就地重试，不能只显示技术错误。

### ZT.buddy 桌面端

- 左上模式保持 `普通聊天 / ZT.buddy`，但两者共享同一条可滚动的会话时间线。普通聊天只回复；ZT.buddy 对明确任务先展示可读的执行意图和权限范围，再进入执行。
- 聊天不会因为一句“你好”自动开始扫描工作区。只有用户提出明确的文件、代码、检索、整理或执行目标时，才进入“准备执行”状态。
- 执行过程在会话中呈现为三层：简短状态、可折叠步骤日志、置顶的结果与下一步。默认不把原始 JSON 或大量日志铺满屏幕；用户可点开查看证据。
- `+` 统一承载文件、Skills、插件和计划模式；点击 Skill 会扫描本机可用项，选择后以引用 token 插入输入框，不自动执行。
- 权限按钮只表达当前级别与即将授予的能力。需要写文件、运行命令或访问网络时，在发送后/执行前显示一次明确确认；不会把权限开关和模型选择混进同一个菜单。
- 模型菜单显示当前模型、上下文上限 `1M`、已用量、剩余圆环，并在切换模型时保留会话。语音入口保持标准麦克风图标；没有启用真实语音模型时明确为“语音输入准备中”，不伪装为可用功能。
- 宽屏采用聊天主区 + 可收起右侧上下文检查器；窄窗口自动收起右栏，将权限、模型和上下文放入可打开面板，避免三栏同时挤压正文。

## 关键用户流程

### 面试官访问公开网页

1. 打开页面，在浏览器标签页看到金色 ZT.AI favicon。
2. 进入“公开聊天”后，首屏直接看到欢迎语、三个问题示例和输入框；无需理解访客 ID 或模型差异。
3. 提问后，页面即时显示自己的消息与思考反馈；失败时可原地重试，不丢失已输入内容或附件。
4. 需要继续上次内容时打开聊天记录；需要一份正式材料时下载与当前语言匹配的简历。

### 桌面端使用者完成一项任务

1. 选择 `普通聊天` 时，任意一般提问按聊天回复，不调用本机工具。
2. 切到 `ZT.buddy` 或明确提出任务后，系统简要说明将做什么、准备使用什么工具、哪些动作仍需确认。
3. 用户确认后，任务以紧凑时间线推进；日志可展开，最终结果包含完成内容、变更文件/链接和下一步建议。
4. 新建聊天、切换模型、引用 Skill 或上传文件都不清空此前会话，且每个动作有清晰的可见结果。

## 组件与状态边界

| 单元 | 职责 | 依赖 | 验证方式 |
| --- | --- | --- | --- |
| `FaviconAssets` | 生成并引用 ZT.AI 标签页图标 | 现有 `zt-logo.png` | 生产 HTML 指向带 base path 的图标，线上返回 200 |
| `PublicChatEmptyState` | 欢迎、示例问题、输入聚焦 | i18n 文案、聊天状态 | 示例问题、主按钮、三语切换均可用 |
| `ChatHistoryDrawer` | 当前访客会话浏览与新建 | visitor-local 状态 | 无跨访客会话；不重复展示新会话 |
| `DesktopIntentPresentation` | 显示普通聊天或执行准备状态 | 现有 intent router、权限状态 | 问候语不触发工具；任务有计划和确认 |
| `ExecutionTimeline` | 紧凑展示状态、日志、结果 | agent task events | 完成日志折叠，结果与失败恢复清晰 |
| `ContextAndPermissionPanel` | 按需显示模型、1M 用量、权限 | 模型/权限状态 | 窄窗不压缩主会话，焦点可达 |

## 文案与交互原则

- 用用户目标命名动作，例如“了解蔡宙廷的选品流程”，不用“开始会话 #4BFDF7”。
- 所有异步动作先回显“正在准备 / 正在回答 / 正在执行第 2 步”，成功后说明结果；错误说明用户下一步能做什么。
- 动效只用于反馈状态，不抢占阅读。支持 `prefers-reduced-motion`，首页循环打字和 Logo 呼吸动效在用户要求减少动效时静止。
- 键盘 Tab 顺序依照视觉顺序；焦点环在浅色背景上清晰可见；固定头部和底部导航不得遮挡焦点元素。
- 文件与权限属于高影响操作：附件明确显示名称、大小、移除动作；执行前才请求必要权限，拒绝后提供继续聊天或修改任务的路径。

## 非目标

- 不把桌面 Agent 能力加入公开网页。
- 不改变账户审核、网关、模型供应商、对话隔离或管理员数据权限策略。
- 不上线未经配置的语音克隆、安卓、iOS 或 macOS 能力。
- 不为了视觉效果删除已验证的聊天、上传、模型、简历下载、历史或 ZT.buddy 运行能力。

## 验收与测试

### 功能回归

1. 公开网页的首页、公开聊天、项目、简历、下载页和三语切换可用；会话隔离、模型切换、文件上传、Markdown、流式输出和简历下载不回归。
2. favicon 在本地构建及 GitHub Pages 子路径下均可正常加载，页面标题与图标一致。
3. 公开聊天的示例问题、历史抽屉、新建聊天、附件、失败重试和输入保留可用。
4. 桌面端的普通聊天、明确任务、权限确认、Skill 引用、模型切换、上下文环、新建聊天和执行结果可用。
5. “你好”“介绍一下你自己”等普通聊天不会触发 `list_workspace` 或任务 API；明确文件/代码任务可进入执行流。

### 人因与视觉检查

1. 在 1440px 桌面、390px 手机和 320px 窄屏检查：输入框均可见、可点击、没有横向溢出和被底部导航遮挡。
2. 对主要按钮、图标按钮、抽屉关闭、新建聊天、发送、附件和权限菜单进行鼠标、触屏尺寸与键盘 Tab 检查；主要触控区域目标为 44–48px。
3. 检查空状态、慢响应、网络失败、无历史、无权限、无可用 Skill、附件错误七类状态的文案、重试与焦点恢复。
4. 使用真实生产构建而不是静态截图验证导航、交互、控制台无错误和产物文件；桌面安装包只在这些检查完成后才生成。

## 研究依据

- Apple 的界面指南指出，空状态应告诉用户下一步能做什么，并提供对应操作入口。
- WCAG 2.2 要求在等效 320 CSS px 宽度下不丢失功能，并关注焦点不被固定内容遮挡。
- web.dev 建议移动端实际触控目标约 48dp 且彼此保留间距。本项目将以 44–48px 作为实现目标。
