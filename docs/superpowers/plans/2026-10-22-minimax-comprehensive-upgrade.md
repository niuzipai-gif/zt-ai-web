# ZT.AI MiniMax 能力升级方案

日期：2026-10-22；状态：第一批模型适配与受控流式语音已实现并通过本地测试，分阶段发布中。本文不是全部已上线清单。

## 目标与边界

在现有 ZT.AI 上增强自然语音对话、三语发音、模型与工具兼容、多模态输入和媒体生成。首先解决等待、截断、打断与错误恢复，再增加功能。

- 保留用户已认可的中文音色及其生产参数；英日语单独做对照，不擅自换成系统或其他人的声音。
- 保留现有 Firecrawl / Tavily / 知乎 / TinyFish / DuckDuckGo 检索和来源抽屉、基础文件解析、项目动画、简历模板。
- 不使用 computer-use 操作用户电脑。不读取、记录或提交 API Key。公共前端不得包含上游凭据。
- 不删除 `.design-audit/`、`.runtime-qa/`、`output/`。分批改动、测试、发布；不捆绑无关重构。
- 新音色正式激活、新服务采购、计费方式变更和无上限压力测试不在本计划的默认执行权限内。先核对已有账户能力与既定测试额度；涉及额外费用先明确预算。
- 外部服务、网络和浏览器不能保证永不出错；目标是可恢复、无静默失败、无重复发送与扣费风险、不丢输入、不串台。

## 官方资料核对与接口边界

核对方式：读取官方文档总目录、发布记录，并重点核对下列与本项目有关的指南、参数和事件契约；不是声称逐字审计了全部商务与接入教程。

1. [模型发布记录](https://platform.minimax.cn/docs/release-notes/models)、[文本模型指南](https://platform.minimax.cn/docs/guides/text-generation)：M3.1 Flash 正式版于 2026-10-19 发布；支持文本/图片/视频输入与不同推理深度。按实际端点选择参数，不混用不同兼容协议。
2. [ASR 指南](https://platform.minimax.cn/docs/guides/speech-to-text)、[接口](https://platform.minimax.cn/docs/api-reference/speech-to-text)：省略 language 请求头可混合语言识别；SSE 是上传后逐步返回，不支持音频流式输入。时间戳/说话人/字幕格式与流式 JSON 互斥；上游上限 500 秒、50 MB 不代表公共站应直接放宽到同样上限。
3. [双向流式 TTS](https://platform.minimax.cn/docs/api-reference/speech-t2a-websocket-bidi)：可连续输入文本，有 sentence_start/end、task_cancel、task_flush；取消后可继续当前连接；空闲超时、队列满、重复 task_start 的处理不同。
4. [TTS 参数](https://platform.minimax.cn/docs/api-reference/speech-t2a-http)：发音字典支持英文 IPA、日语假名和读法替换。字典仅用于语音层，不把音标/注音插入用户可见回复。`text_normalization_mode=quality` 有模型/非流式限制和额外延迟，不能直接宣称在全部实时通路生效。
5. [音色复刻指南](https://platform.minimax.cn/docs/guides/speech-voice-clone)、[复刻接口](https://platform.minimax.cn/docs/api-reference/voice-cloning-clone)、[官方候选音色对照方案](https://platform.minimax.cn/docs/solutions/voice-id-lucky-draw)：支持干净样本与短参考音频/对应文字；文本验证分数不是音色相似度，接口成功不等于声音像本人。
6. [服务端工具](https://platform.minimax.cn/docs/guides/server-tools)：原生 web_search 通过 Anthropic Messages / OpenAI Responses，非当前 Chat Completions。须消费工具结果与引用；遇到 pause_turn 要预算内继续，不能显示原始调用或当成最终回答。
7. [Responses](https://platform.minimax.cn/docs/api-reference/responses-create)：有独立流式事件契约；store、previous_response_id 等兼容字段目前被忽略，不能依赖它们保存多轮上下文。
8. [提示词缓存](https://platform.minimax.cn/docs/api-reference/text-prompt-caching)：稳定前缀和命中指标有用；动态时间与检索结果不能污染稳定前缀，但仍必须在每轮正确注入。
9. [图生图](https://platform.minimax.cn/docs/api-reference/image-generation-i2i)：subject_reference 当前为 character 人物参考，不承诺通用商品图局部编辑，也不当作反向搜图。
10. [视频 V2](https://platform.minimax.cn/docs/api-reference/video-generation-v2-create)：H3/H3 Max 的参数档位不同，首尾帧与多模态参考模式互斥；按具体接口和账户探测确认，不能只看模型概览表。
11. [计费](https://platform.minimax.cn/docs/pricing/overview)、[M Plan FAQ](https://platform.minimax.cn/docs/m-plan/faq)：订阅 Key 与按量 Key 不混用；模型能力不能推导到账户已开通。公开站需配额、并发控制与成本记录，不静默切换计费方式。

## 阶段一：协议与观测基线

涉及：`server/src/contracts/chat.js`、`server/src/providers/minimax.js`、`server/src/providers/openai-compatible.js`、`server/src/telemetry.js`，及桌面对应模型路由。

- 建立正式版/Preview 和各端点能力表；升级正式 M3.1 Flash 时保留 reasoning 分离、取消和多模态，不把内部思考/工具标记泄漏到用户回复。
- 对普通闲聊用较低推理强度，复杂分析按需提高；用户指定深度优先。沿用既有“讲清楚、举恰当例子、闲聊不硬推工作背景”的规则。
- 先加 Responses 独立适配器及固定事件样本测试；需要原生工具的请求再选择该通路，普通对话不被迫一次性全部迁移。
- 记录 request/trace ID、首字延迟、完成原因、使用量和缓存命中；区分正常结束、长度截断、服务错误、断流和主动取消。日志不保存原始录音、密钥和完整私人内容。
- 预检模型/音色/区域/账户权限；现有可用配置作为回滚基线。查额度不等于购买额度。

验收：普通/图像/多轮、不同 effort、工具结果、跨 chunk 标记、断流等适配测试通过；取消不再输出；能力不符有清晰降级，不丢 history。

## 阶段二：语音主链路（优先级最高）

涉及：`server/src/providers/mmx.js`、`server/src/voice-service.js`、`server/src/index.js`、`src/components/VoiceMode.jsx`、`src/lib/voice-{audio,client,mode}.js`、`src/main.jsx`；桌面 `agent-desktop/public/voice-*.mjs`。

- 后端代理上游双向 TTS，浏览器不拿上游 Key。握手限制来源、绑定会话、限制连接/文本/队列和空闲时间；公开访问也要有滥用防护。
- 模型正文流通过保留句界的语音文本转换器进入 TTS；工具/思考/代码/长链接不被朗读。末尾必须 flush，音频完整结束才显示播放结束。
- 播放使用受控音频队列与 AudioWorklet 能力检测；不支持时降级已有 HTTP 音频。首句从第一个采样播放，预热不得消耗语音；只在实际音频输出阶段显示正在说话。
- 本地 VAD 与录音切段处理连续说话、停顿和自动提交；ASR 返回流式文字但不假装原生实时输入。保留用户手动发送/编辑/重试和独立听写入口。
- 打断同时停止本地旧音频、取消上游合成、取消旧生成，并通过 turn/generation ID 丢弃迟到事件；打断录音保留起始预卷，避免丢访客开头几个字。
- 回声消除、持续语音阈值、耳机/扬声器差异测试，避免系统把自己的回答当访客。静音时光球不假动。
- 区分空闲心跳、断线重连、队列背压、额度错误；重连不重复问题、不重复已播首句。失败时保留已完成回答与录音。
- 延续用户首次点击后的音频解锁；明确浏览器策略限制，不能保证无任何用户操作即可有声自动播放。被拦截仍提供可用的一次点击恢复。

验收：三语开场完整、键入问题也可语音回答、连续至少 10 轮、自动语言切换、长短停顿、首句/中途/末句打断、切换页面返回、设备变化、重连、超时、429/5xx 和手动重试均有可复现记录。统计首音 p50/p95、取消到静音延迟、丢字/重复/误打断；先测基线再公布改善比例，不预先虚报指标。

## 阶段三：保留本人音色的英日语校准

- 中文使用现有版本作为保护对照，不混改。
- 先对已有录音分析格式、有效人声、底噪、削波和响度；仅裁切无效静音、修正格式等可解释处理，原始录音只读且不上传仓库。
- 英语按词义配置 IPA/数字/缩写读法；日语配置人名、地名、数量词和日期读法；读法仅进 TTS 字典。
- 对比当前慢速+固定 calm 与自然语速/自动情绪；短句与混合语言独立测试，不把慢速当作发音修复。
- 有明确预算后才生成少量候选个人音色，以相同固定脚本做盲听对比；保留当前 voice ID，不先激活大量候选。
- 分开评估相似度、可懂度、韵律和读音；机器转写可查漏读，但不能替代本人/熟人试听，也不能承诺完全消除跨语种口音。

验收：中文无回归；英/日固定测试集逐项有对比音频、文本与读音记录；未经实际试听不宣称音色更像本人。

## 阶段四：检索与多模态输入

涉及：`server/src/web-research.js`、现有搜索适配器、`server/src/index.js`、附件与来源组件、对话协议。

- 原生 web_search 作为受控补充/备用，不替换已接服务，也不每轮把所有供应商都调用一遍。
- 基于新鲜度、问题复杂度、来源质量与冲突扩展查询；已有 6→24 预算保留并统一耗时/费用上限。重要结论优先一手来源，失败明确说没有核实，不猜。
- Responses/Anthropic 原生引用映射到现有来源抽屉；完整保存工具上下文，设置最大续接轮数；检索页面内容始终为不可信资料，不能当系统指令执行。
- 音频附件增加转写、说话人、时间戳、摘要与 SRT/VTT；超限内容给明确提示，长音频切段保留时间偏移，跨段说话人不能无证据强行合并。
- 视频按模型可用的原生视频输入或抽帧+转写方式理解；视觉与音频证据分开说明，不把仅看画面宣称听懂音轨。
- 原有表格/PDF/DOCX 解析继续使用，保留真实单元格/页码/引用范围；不把官方文件上传端点误当通用办公文档解析器。
- 外部 URL/附件需体积、时长、格式与 SSRF 防护；私有资料不以公开链接传播，不静默永久保存。

验收：中文/英日新闻、明确搜索、陌生实体、图片追问、冲突来源、服务全部失败、录音和视频附件均输出可审计证据；来源数可随情况变化而不是拼凑数量。

## 阶段五：生图与视频任务体验

涉及：`server/src/providers/mmx.js`、生成任务接口/存储、前端附件和生成结果卡片、桌面媒体调用。

- 生图增加可选比例、尺寸和受支持的人像参考；保持 image-01，按用途可选 image-01-live。商品图编辑与反向搜图不冒充已支持。
- H3/H3 Max 增加首尾帧或多模态参考输入和参数验证；不支持的组合提交前拦截，默认不自动选择最贵档位。
- 从“长时间卡住聊天轮询”改为任务卡片：提交、排队、生成、成功/失败、可恢复查询；未知提交结果先查询而非盲目重复生成。
- 绑定任务所有者和输入摘要，任务 ID 不作为访问授权；存储必须经过可持久化条件核对，不把 Render 临时文件当永久任务数据库。
- 刷新/断线后恢复状态；取消仅在供应商允许的状态生效。若采用回调，回查官方任务状态验证通知，不信任任意回调请求。
- 控制访客额度、成本、并发和资源保留时间；模型权限或额度不具备时清晰说明并使用明确允许的已有通路。

验收：参考图确实传入、长任务不堵聊天、刷新后可继续查、失败不重复扣费、结果可播放/下载；模拟并发为主，线上付费样本严格限量。

## 阶段六：跨端回归与发布

1. 先补阶段相关回归测试，使用模拟上游覆盖协议/故障/并发，再执行有预算的真实端到端验证。
2. 用独立无头浏览器测试桌面/手机尺寸、合成麦克风与音频解码，不操控用户现有浏览器；设备路由和扬声器听感无法用无头测试替代。
3. 网页、桌面、Android 逐项核对共享代码和打包差异；不把网页更新当成已安装客户端更新。物理 iOS/Android 未测时明确注明。
4. 模型适配/语音流式/原生搜索/新媒体模型分别开关，保留旧 HTTP 路径和可用个人音色，按阶段灰度。
5. 发布后核对 main、Pages 静态资源版本、Render revision 和实际新旧客户端请求；结果附测试清单、失败项、指标和回滚点，不只看 HTTP 200。
